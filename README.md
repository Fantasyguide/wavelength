# Returned 逆转录者

本地 / 局域网可玩的《逆转录者（Returned）》，基于《Wavelength（心灵波长）》桌游：两队对抗，Psychic 出题，队友拨杆猜目标位置，对方猜左右。开局可选「原版」或「平衡快局」。

## 文件结构

| 文件 | 作用 |
|---|---|
| `index.html` | 游戏界面结构(本地热座 + 联网控制器/监视器,自动识别) |
| `app.css` | 游戏界面样式 |
| `assets/fantasyguide/` | 幻想指南风格的本地字体、装饰边框、阴阳分隔线和背景素材 |
| `app.js` | 界面渲染、离线模式和联网客户端逻辑 |
| `game.js` | 共享游戏引擎(纯逻辑,浏览器和 Node 通用) |
| `target-sampling-config.js` | 平衡快局的目标采样配置；本地与服务器共用，仅通过编辑文件调整 |
| `server.js` | Node 服务器:SSE 实时广播 + API + 静态文件服务 |
|  `cards.yaml` | 默认题库(服务器启动时加载) |
| `decks/` | 服务器题库收藏夹,放入的题库文件可在 iPad 上直接下拉选择 |
| `config.json` | 服务器配置(访问密码),已 gitignore |
| `auth-sessions.json` | 已认证浏览器的设备会话(自动生成,仅保存令牌哈希,已 gitignore) |

## 两种玩法

### 1. 本地热座(单设备)

直接双击打开 `index.html` 即可,无需任何服务器。所有玩家围着一个屏幕轮流操作。

### 2. 联网模式(多设备实时同步)

服务使用 **Node.js 22.23.4 LTS**（[2026-10-21 安全更新](https://nodejs.org/en/blog/release/v22.23.4/)），版本固定在 `.nvmrc`。使用 nvm 时，先在项目目录执行 `nvm install && nvm use`。

先在 `config.json` 设置非空 `password` 作为控制器密码，再启动服务：

```
node server.js
```

启动后控制台会打印访问地址(本机 + 局域网 IP)。各设备用浏览器打开 `http://<电脑IP>:3100`,选择角色:

- **🎮 控制器**(建议 iPad):验证密码后负责所有操作——Psychic 看目标位置、选卡片面、拨动拨杆、锁定、猜左右、开始下一轮
- **👀 监视器**(建议电脑/大屏):无需密码，实时观看战况；揭晓前不会收到目标位置，揭晓后显示答案及复盘
- **🎲 本机游玩**:无需密码，在当前设备独立进行热座游戏，不影响联网对局

超宽活动屏按 **3904 × 672 实际像素、100% 浏览器缩放**设计：左侧、中央游戏区、右侧分别为 960 / 1928 / 960px 宽。左队的队名、比分和进度在左侧，右队在右侧；左队下方显示轮次记录，超出空间时自动滚动。候选题目 64px、选定概念 100px、阶段提示 56px、轮次记录正文 48px。队名使用对应队色，常规队名为 116px，上下各留半个字号；长队名根据剩余宽度缩放，比分 208px，进度菱形边长 28px。概念之间的黑色 VS 使用思源宋体 SemiBold（600）并固定居中：候选阶段 48px、两侧各留 20px 间距；选定后 80px、两侧各留 28px 间距。超出结算门槛的每 1 分，在菱形之后增加 1 个实心圆（例如 9 分显示 8 个菱形加 1 个圆）；圆与菱形的外轮廓宽高一致。行动队卡片的两层边框及中间空隙一并填成队色，组卡片不再显示灰色方向箭头。出题结束后只显示选定题面；题卡、提示、左右选择、色带和结算分别保留固定位置，整个回合不会因新增信息上下跳动。200% 系统缩放对应的 1952 × 336 视口按相同比例适配。

显示使用 **左 −100%、中 0%、右 +100%** 的刻度。控制器点击「规则速查」会同步打开或关闭监视器的规则说明。监视器在终局后直接进入复盘，展示获胜队伍、最后一题和轮次记录，无需点击「返回复盘」。

## 游戏流程

1. **设置**:填两队名称，选规则版本、先手、题库和出题方式，开始游戏。默认「平衡快局」规则与「二选一」出题：每轮抽取两道题，由出题人点击选择一道后继续；也可切换「原版」规则或「经典单题」。
2. **出题**:转录员选卡片面 → 点「查看目标」偷看目标位置(**其他人别看屏幕!**)→ 口述一个落在两个概念之间的线索 → 关闭蓝条，**直到本队锁定游标前必须保持沉默**。
3. **讨论**:本队讨论线索，把金色游标拖到猜测位置并锁定。若转录员在此期间说话，点击锁定按钮旁的「说话处罚」并确认：游标在整条刻度（−100% 至 +100%）上均匀随机放置并立即锁定，随后正常进入对方猜左右；取消确认不会改变游标或阶段。本机和联网控制器均可操作，监视器只同步结果；开启 THCCB 联动时，处罚也会先确认封盘。
4. **猜左右**:对方猜目标中心楔形在拨杆左边还是右边
5. **揭示**:Psychic 揭示目标——本队得 2/3/4 分(边界取高),对方猜对左右得 1 分(本队完美命中 4 分时对方不得分)
6. 按所选规则结算；如果继续，开始下一轮并更换出题人。一队完成一次出题与结算算一轮，两队各行动一次共两轮。

### 规则版本

| 项目 | 原版（保留本项目现有规则） | 平衡快局（默认） |
|---|---|---|
| 起始分 | 先手 0，后手 1 | 双方 0，不补分 |
| 色带基准宽度 | 默认 40，可在高级选项修改 | 固定 48 |
| 目标分布 | 第 1 轮适中，第 2 轮明显，之后推荐 | 所有轮次推荐 |
| 行动顺序 | 4 分且仍落后时再行动一轮 | 严格交替，无追赶连动 |
| 常规结算 | 先到设定分（默认 10）即结算；最多 10 轮 | 第 4 轮结束，有队达到设定分（默认 8，可调整）则比较总分；否则第 6 轮结算 |
| 提前结束 | 沿用原版结算 | 每轮揭示后，落后方已无法追平则立即判领先方获胜 |
| 平分加时 | 两队各一次，仍平则重复 | 两队各一次，仍平则和局 |
| 总轮数 | 常规最多 10 轮，加时不限 | 常规通常 4–6 轮，胜负已定可提前结束；含加时最多 8 轮 |

两种规则均在结算时由分数较高者获胜，平分进入加时。加时比较独立得分（包含猜左右的 1 分），主记分板保持常规赛的平分；界面另行显示两队加时分和是否已出题。加时必须等双方各出一次题后才结算，原版追赶规则不适用于加时。

平衡快局每轮揭示并计分后检查胜负。正常结算时，第 4 轮有队达到设定分数就比较总分，否则第 6 轮结算；平分加时。若落后方已不可能追平，则提前判领先方获胜，可以不等满 4 轮或双方行动次数相等。判断方法：已有队达到设定分数时，计算到最近一次正常结算（第 4 或第 6 轮）的剩余机会；否则计算到第 6 轮。落后方每次本队出题最多追回 4 分，每次猜左右最多追回 1 分；只有当前分差严格大于这些机会的合计上限，才提前结束，能追平仍继续。在默认 8 分下，第 3 轮 8:3 可提前结束，8:4 必须继续；第 4 轮 7:1 可提前结束，7:2 仍可能追平。平衡快局宽度固定 48，获胜分数默认 8，在主设置区直接调整，无需展开高级选项；填 0 关闭分数门槛，仍保留六轮封顶与绝杀。原版分数门槛默认 10，也可在主设置区调整，填 0 仍保留十轮封顶。

规则版本仅可在开局设置中切换，本地、控制器和监视器使用同一规则状态。点击「再来一局」保留所选版本；切换版本会恢复该版本的默认分数与宽度，不改变题库、出题方式和队名。

### 目标采样文件配置（维护者）

平衡快局默认启用按每队历史调整目标区域概率的软保底，仅编辑根目录 `target-sampling-config.js` 配置。页面的设置、规则说明、提示、复盘及监视器均不展示该机制，也没有调整它的 API 操作。联网修改配置后重启 Node 服务；本地或静态网页修改后重新加载页面。此文件是浏览器本地玩法所需脚本，不是保密凭据存储。

| 字段 | 默认值 | 含义 |
|---|---:|---|
| `enabled` | `true` | 是否启用；设为 `false` 恢复推荐分布的独立抽取 |
| `easyThreshold` | `70` | 公共坐标绝对值严格大于此值为易区；等于时属于难区 |
| `strength` | `0.5` | 对该队累计难易偏差的修正强度，非负 |
| `minEasyProbability` | `0.10` | 下一次易区概率下限，0–1 |
| `maxEasyProbability` | `0.90` | 下一次易区概率上限，0–1，不能低于下限 |

基准易区概率 $p_0$ 根据推荐分布及最终整数目标的取整边界精确积分计算，默认约44.6239%。某队已经抽取 $n$ 题、其中 $e$ 道易题时，使用 $q=\operatorname{clip}(p_0+0.5(np_0-e),0.1,0.9)$；随后先按推荐分布抽候选，再以归一化的 $q/p_0$、$(1-q)/(1-p_0)$ 接受率决定是否保留。这样保持难、易各区域内部的分布。

两队历史互相独立，加时继承，新局或重新开局清零。选题重抽与拒绝的目标候选均不计入历史；最终选题后才计入一次，经典单题的跳过替换本轮目标，不额外推进历史。历史仅保留在引擎私有运行状态中，不进入联网状态广播。原版继续采用其原有分轮分布。

**出题禁忌**：禁用卡片上的词/同义词、数字、复合线索、自造事物。

## 题库系统

### 格式(JSON / YAML 均可)

- JSON:`{"name": "题库名", "cards": [["左", "右"], ["左1", "右1", "左2", "右2"]]}`
- YAML:每行一张卡 `- [左, 右]`;双面卡写 4 个概念 `- [左1, 右1, 左2, 右2]`;`#` 开头为注释
- **2 个概念 = 单面卡**;**4 个概念 = 双面卡**(Psychic 可选"面 A / 面 B"出题)
- 概念文字中请勿使用逗号

卡牌可选填 `tag`：`1` 为偏节目效果，`2` 为普通、容易回答；未填按 `2` 处理。默认题库 `cards.yaml` 的初步标签可逐张修改。旧数组格式继续兼容，也可与带标签的卡混用：

```yaml
name: 示例题库
cards:
  - concepts: [纯情, 海王]
    tag: 1
  - concepts: [高, 矮]
    tag: 2
  - [热, 冷] # 未标注，按标签 2 处理
```

JSON 中对应写作 `{"concepts": ["纯情", "海王"], "tag": 1}`；双面卡的 `concepts` 仍写 4 个概念，共用一个标签。

### 加载方式

| 场景 | 方式 |
|---|---|
| 联网模式 | 把题库文件放进服务器目录的 **`decks/`** 文件夹 → iPad 控制器下拉选择(改动后点「刷新」) |
| 本地模式 | 点「选择文件…」手动选择;或用过的题库自动记住(localStorage) |
| 默认 | 加载根目录 `cards.yaml`（当前为「车万版」，回退 `cards.json`）；「恢复初始题库」回到这套默认题库，联网模式恢复服务器启动时加载的内容；无默认文件时回退内置 98 张卡 |
| 通用题库 | 原内置 98 张卡保留在高级选项的「其他题库」→「通用题库（原内置）」，本地和联网控制端均可选择 |

## 控制器密码与免密观看

`config.json`:

```json
{
  "password": ""
}
```

- 联网页面先选择「控制器」「监视器」或「本机游玩」。只有进入控制器需要输入密码；监视器观看联网战况、本机热座游玩都不需要密码。
- `""`（空）表示尚未配置控制器密码，此时不能操作联网对局，仍可观看战况或本机游玩。设置非空密码后重启服务。
- 控制器认证成功后使用独立的 HttpOnly 设备 Cookie，同一 IP 下的其他设备不会自动获得控制权限；已登录设备再次选择控制器无需重复输入。
- 会话有效期 180 天并记录在 `auth-sessions.json`(只保存令牌哈希),重启服务器无需重输;修改密码或删除该文件可重置所有设备
- `POST /api/logout` 可撤销当前设备会话;从旧版升级后,原 `auth-ips.json` 不会迁移,各设备需重新登录一次
- 密码只保护**联网控制**，包括操作游戏、管理题库和 THCCB 配置。本机游玩使用独立状态，不影响联网对局。
- 公开的 `/api/stream`（或 `?role=monitor`）不需要密码，未揭晓的目标位置不会发送给观众；已揭晓目标、得分和复盘正常同步。只有通过认证的 `/api/stream?role=controller` 才能读取隐藏目标和 THCCB 联动状态。
- 密码比对使用时序安全比较；未认证的控制请求返回 401，未配置密码时返回 403。撤销会话后，已有的控制器数据连接也会关闭。

## 网络稳定性(现场网络不稳友好)

- **连接状态指示**:页头徽章显示 已连接(绿)/ 重连中(橙,脉冲)/ 连接断开(红),断开时弹出警示横幅并自动禁用操作按钮
- **自动重连**:断线后 1s→2s→4s…→最大 10s 指数退避重连,连上即重置
- **心跳探测**:每 8s ping 一次,连续 2 次失败强制重建连接(兜底 WiFi 掉线等 SSE 不报错的情况)
- **操作队列**:断线期间的操作自动入队,重连后按序补发(连续拨杆只保留最新值)
- **iPad 唤醒**:页面回到前台立即心跳 + 补连
- **服务器保活**:每 15s 发送 SSE 保活帧,防止热点/代理空闲超时掐断连接

## iPad 使用

**单机本地玩**:把 `index.html`、`app.css`、`app.js`、`game.js` 和完整的 `assets/` 目录放在同一目录(可以直接复制整个文件夹),AirDrop/存入 iPad「文件」App,用 **Documents by Readdle** 等文件浏览器打开 `index.html`,自动进入本地热座模式(注意:直接双击文件是打不开的,iOS 需要这类 App 运行 HTML)。

**多人联机**:电脑跑 `node server.js`,iPad 用浏览器访问局域网地址,选「控制器」即可;电脑开监视器观看。

## 在线托管(无后端版,任何人打开网址即玩)

把仓库的**整个根目录**(或仅 `index.html` + `app.css` + `app.js` + `game.js` + `cards.yaml` + `names.json` + 完整 `assets/` 目录)当作静态站点部署到任意静态托管,访问者打开网址即可直接玩**本地热座版**——页面会自动检测到没有后端并进入本地模式。

- 仓库保持私密即可;**`config.json`、`auth-sessions.json` 已被 gitignore,不会随仓库暴露**
- 部署在第三方平台时,托管的是仓库内文件的公开副本(只有游戏代码,无任何秘密)
- 联网模式(控制器/监视器、密码)是 `server.js` 的功能,只能在你自己运行的 Node 服务器上生效

### Netlify(推荐,免费)

1. 打开 https://app.netlify.com 用 GitHub 账号登录
2. Add new site → Import an existing project → 选择私密仓库 `wavelength`
3. Build command 留空 / Publish directory 填 `.`(仓库根目录)
4. Deploy 完成后得到 `https://<名称>.netlify.app` 网址,可自定义域名

### Vercel(免费)

1. 打开 https://vercel.com 用 GitHub 登录
2. Add New Project → Import 私密仓库 `wavelength`
3. Framework Preset 选 Other / Build Command 留空,Deploy
4. 得到 `https://<名称>.vercel.app`

### Cloudflare Pages(免费)

1. https://dash.cloudflare.com → Workers & Pages → Create → Connect to GitHub
2. 选择私密仓库,Framework 选 None,Build command 留空,Build output directory 填 `.`

部署后访问者打开网址即可玩;本机开发/局域网联机仍用 `node server.js`。

```json
{
  "gameName": "Returned",
  "gameTitle": "Returned",

  "psychic": "Psychic",
```

## 开局设置与高级选项

主设置区直接提供规则版本、获胜分数、先手和出题方式。高级选项包含题库、文案、出卡顺序和原版色带宽度。

- **题库 / 文案**:服务器下拉选 decks、本地文件选择、恢复初始题库（默认车万版），原内置卡片另设「通用题库」入口；文案可恢复默认
- **按顺序出卡**:不洗牌；二选一仍按标签概率选池，各池按固定顺序出卡，抽完循环。
- **二选一（默认）**:每轮先等待点击「揭示卡片」，随后显示两道不同的候选题并开始 10 秒倒计时。左侧 70% 抽标签 1、30% 抽标签 2，右侧 70% 抽标签 2、30% 抽标签 1；每个标签池独立抽完循环，缺少该标签的可用题时回退到另一类。选题固定倒计时 10 秒，宽限结束仍未选则自动选择：一张标签 1、一张标签 2 时分别为 70% / 30%，与左右位置无关；标签相同各 50%，无标签按标签 2。选定后才生成目标并进入出题流程，查看目标后才开始出题/拨杆计时。未选中的题同样计为已抽取。题库只有一道不同的题时，展示该题供确认，超时直接选该题。双面卡选定后仍可选择卡片面。
- **重新抽选**:二选一选题阶段，双方每整局各可重抽一次，两道候选题一起替换，点击「揭示卡片」后重新倒计时 10 秒，轮数不变，优先避开刚展示的题；小题库允许复用旧题。同队后续轮次及加时共享这一次机会，重新开局恢复。选定后不能跳过；经典单题保留跳过功能。
- **色带宽度**:以设置中的基准宽度为准，4 分区为 80%，每侧 3 分区为 100%，每侧 2 分区为 110%；默认平衡快局基准固定为 48，原版基准为 40、可修改。
- **获胜分数（主设置区）**:平衡快局默认 8 分，原版默认 10 分，均可调整为 0–999 的整数；填 0 表示不设分数门槛（计分轨道显示 ∞），仍保留各自轮数上限。自定义值在开局和再来一局时保留；切换规则版本恢复该版本默认值。
- **倒计时**:点击「揭示卡片」后选题 10 秒；查看目标后，出题和拨杆共用 60 秒；锁定后先等待，点击「判断左右」才显示左右选项并开始 15 秒倒计时。两个等待阶段均不计时，刷新或重连也不会自动开始。所有倒计时归零后显示 `00:00` 并给予 1.5 秒宽限，期间仍接受操作，宽限结束才自动处理：选题按上述标签概率；拨杆当前不在 0% 时直接锁定当前位置，仍在 0% 时才在整条刻度上均匀随机选择（拨动后又回到 0% 也按随机处理）；猜左右各 50% 并进入待揭示阶段。手动锁定、超时自动锁定和说话处罚锁定都进入同一个等待判断阶段，需点击「判断左右」继续。联网模式以发起该阶段操作的操控端为准：点击「揭示卡片」后的选题（包括重抽）和点击「判断左右」后的猜左右，在该端显示后才开始完整的阶段时长；查看目标时立即显示并开始本地 60 秒，服务器确认不会重置这段时间，隐藏目标后讨论继续共用它。其他操控端和监视器在等待开始时显示 `--:--`，开始后直接跟随发起端每秒报告的剩余时间、预警和归零音，不独立推算截止时间。查看目标的首次进度随操作一起发送，使显示器无需额外往返确认即可显示 60 秒。每段计时有独立标识，刷新、重连、重复确认和过时消息不会重新赠送时长。操控端正常报告时，仅在其完整时长及 1.5 秒宽限结束后通知服务器自动处理；连续 6 秒收不到新进度时，服务器才按最后报告启用断线兜底；若 30 秒内一直没有开始确认，则启用服务器计时，避免永久等待。网络延迟会使跟随端稍晚显示或跳过中间秒数，不能保证多设备声音同时响起。1.5 秒宽限从操控端归零开始，包含 0.75 秒长音的播放时间。本地页面休眠后恢复会补处理已到期阶段。出题/拨杆计时剩余 10 秒时预警，选题和猜左右剩余 5 秒时预警：变红并播放一次约 0.25 秒的短音。归零时播放一次 0.75 秒长音，宽限结束不重复。两种音效均为 880 Hz 正弦波，峰值增益 0.32，实际响度取决于设备音量。可修改 `index.html` 的 `data-dial-timer-seconds` / `data-guess-timer-seconds`，设为 0 可关闭相应计时。
- **刻度**:在 5% 到 95% 之间固定每 5% 一条,横条下方标注 0% / 25% / 50% / 75% / 100%;两端只显示数字,不画刻度线
- **目标分布**:默认平衡快局所有轮次使用推荐分布；原版第 1 轮使用适中分布，第 2 轮使用明显分布，第 3 轮及以后使用推荐分布。

## 得分区配色预览

正式界面采用「雾银靛青」与「箭头引导」：银灰遮挡、蓝白底轨、由浅到深的靛青得分区。对手选择左右后，箭头从游标朝所选端点流动；同侧外框的上、下和端点三边使用该队红色或紫色并加粗。揭晓后停止箭头、保留边框，新一轮清除提示；系统启用「减少动态效果」时箭头静止。

打开 `/design/color-lab/`（或开局设置中的「得分区配色预览」），可切换「纸白青玉」「雾银靛青」「烟墨鎏金」「暖灰岩墨」四套整体方案，每套同时定义遮挡条、空白底轨、2/3/4 分区、刻度和边框。两队默认保留红 `#B52C3A` 与紫 `#8F3D7E`，可在预览中微调。

预览包含 3904 × 672 整屏「遮挡时 / 揭晓后」切换、两个状态并排对照的方案卡和放大条、现有配色对照、灰度检查与色值；链接末尾的 `#celadon` / `#indigo` / `#champagne` / `#graphite` 对应上述四套方案。默认先显示遮挡状态，切换方案时保留所选状态。预览不连接对局 API，选择方案仅改变预览，不修改正式游戏配色或进行中的对局。也可直接打开 `design/color-lab/index.html`，需保留项目资源目录。

「左右选择动效」页签提供半区呼吸、流向光带、轮廓呼吸、箭头引导四套方案，可用 `#direction-pulse` / `#direction-flow` / `#direction-outline` / `#direction-arrows` 直接打开。支持偏左、偏右、未选择、红紫选队、游标位置、得分区配色、暂停与模拟揭晓。高亮区间以游标为界，颜色跟随作出选择的队伍；揭晓前隐藏目标和本轮结果，揭晓后停止循环并保留方向轮廓。系统启用「减少动态效果」时显示静态提示。所有操作仅作用于预览。

动效中的配色选项会同时切换遮挡与得分区；浅色遮挡使用红紫本色的透明提示，深色遮挡使用提亮后的提示。`?palette=indigo#direction-arrows` 可直接查看正式采用的组合及加粗边框，刷新和打开分享链接仍能看到相同搭配。

### THCCB 资金联动

联动通知使用 `/api/v1/returned`，对应 THCCB 观众页 `/returned`。两端须配套更新；已有密钥和配置继续使用。

联网时，顶部并排显示「THCCB」和「RETURNED」连接状态，控制器与免密观战均可见。THCCB 在启动、保存配置后及每 30 秒通过只读 `GET /api/v1/returned/current` 检测可达性，超时为 4 秒；未启用时不检测，本地模式不显示联动标识。RETURNED 断线时，THCCB 显示「状态未知」，避免沿用旧的已连接状态。连接徽标只表示接口可达性；业务操作失败、旧轮清理和退款进度独立显示在游戏操作按钮下方及管理员菜单中，不会被健康检测成功清除。公开状态仅包含连接状态及检测时间，不包含配置、密钥或未揭晓答案。

结果 POST 成功约 500 毫秒后，服务器会使用同一密钥调用 `GET /api/v1/returned/rounds/{round_key}/results`，将最接近目标的五名观众、竞猜位置、误差和到账金圆券同步给控制器与监视器。从“结算”出现起展示榜单，终局复盘仍保留；下一轮、重新开局、关闭联动或作废后清除旧榜单。只有本轮已关联的竞猜显示 `assets/thccb-qr.png`；未开盘、未联动或取消时显示暂停提示。二维码按卡片可用宽高等比放大，保留图片原有白边。榜单沿用旧群友竞猜的装饰边框和大字昵称，不显示头像；3904 × 672 大屏采用 40px 标题、36px 昵称及排名、32px 数值，卡片内自动滚动显示完整五名。GET 失败只显示提示，已经完成的结算不受影响；可在 THCCB 竞猜页查看。榜单位置按本页现有 −100%～+100% 刻度换算，排名及金额与 THCCB 一致。

榜单偏差按“竞猜位置 − 目标位置”计算，换算为本页刻度的百分点，保留一位小数：正数表示偏右，负数表示偏左，零显示“正中”。竞猜位置保持灰色；“正中”独占翠绿色 `#008544`，任何非零偏差立即切换到明显不同的黄绿色。非零偏差采用 `hsl(H(abs(d)), 65%, 28%)`，其中 `d` 为带符号的偏差。色相参考奖励档位，以 `(绝对偏差, 色相)` 的 `(0, 100°)`（仅作为非零偏差趋近零时的插值起点）、`(3.2, 90°)`、`(11.2, 70°)`、`(20, 40°)`、`(30, 0°)` 为节点做分段线性插值，由黄绿经橙色渐变到深红；超过 30 个百分点保持深红，正负同幅偏差使用相同颜色。颜色只用于显示，到账金额仍使用 THCCB 回传值。

显示端在揭晓且收到本轮前五名后，在刻度轴下方同步显示 A2 实心号码牌；操控端不绘制。1—5 对应榜单名次，64px 彩色方牌配 44px 白色粗体数字，牌面与落点沿用偏差颜色，随大屏比例缩放。每个圆点保留真实竞猜位置，用从 6px 逐渐加宽到 18px 的引线连接各自号码牌；相近或重合时只将号码牌横向错开，保持独立且不遮挡，端点向内避让。编号按位置从左至右排列，完全重合时按名次排序。观众标记绘制在轴边框、猜左右标识框与游标之上，在 −100%、−50% 等刻度文字之下。终局复盘保留；进入下一轮、重置或本轮不再关联竞猜时，清除全部落点与号码牌。等待结果、无观众或加载失败时不显示旧标记。

联网控制器的「高级选项」可配置 THCCB 站点地址和联动密钥。右上角「管理员」菜单提供联动开关、说话处罚、重试联动、作废本轮和重置本局；状态短句位于“目标在左”等游戏操作按钮下方。联动默认关闭。先在服务器 `config.json` 中设置非空 `password` 并重启，使用共享密码登录后才能读取或保存联动配置。系统沿用共享密码认证：任何持有该密码的设备都可以选择控制器并修改联动配置，没有单独的管理员账号。

地址填写 THCCB 站点根地址（支持带部署路径），仅接受 http/https，不能包含用户信息、查询参数或片段。两端密钥须一致且至少 32 字符；保存时密钥留空会保留原值。密钥仅保存在服务端 `config.json` 的 `thccb` 对象内，不会返回浏览器或共享游戏状态。保存立即生效并保留 `password` 等已有配置；写盘失败会明确报错。服务端只提供游戏页面、素材和题库等公开静态文件，配置、认证存储、服务端代码及 Git 文件不可通过静态地址读取。

转录员完成出题、关上遮挡条时开盘；锁定（含说话处罚）或讨论超时时封盘；揭晓发送整数目标位置。正常关键操作等待 THCCB 确认；网络失败后在管理员菜单重试。等待只冻结相应阶段，管理操作不等待网络。出题直接超时而没有讨论竞猜时段时，不补开一轮瞬间封盘的竞猜。

关闭联动立即继续本地已提交的动作，作废和重置立即丢弃旧动作；封盘等待解除后，点击「判断左右」才开始完整的猜左右倒计时。未结算竞猜的取消、退款在后台同步，离线时不能保证立即退款。局中重新开启只在下一次关上遮挡条时开盘；尚有待清理旧轮时跳过本轮竞猜，清理完成不在讨论中途补开。

作废本轮保留当前队伍及轮次，恢复轮初成绩、补轮、加时、胜负、复盘和重抽机会，再随机抽题、目标；二选一回到等待揭示卡片。允许作废刚揭晓甚至刚判定结束的一轮，但 THCCB 已发奖励保留。重置未结束的对局回到开局设置，保留队名、题库和规则；正常终局弹窗和返回复盘后的主操作区均可点「再来一局」。重复或过时管理指令按操作 ID 与轮次标识拦截，管理指令不进入浏览器断线缓存。

服务端私有 `data/thccb-journal.json` 保存轮号、取消/结算意图及重试记录（可用 `WL_BRIDGE_STORE` 覆盖；默认位于配置文件所在目录的 data 下）。原子替换并同步磁盘，权限 0600，不含联动密钥、不对外提供。取消任务最多每 60 秒退避重试；权限错误需手动重试。重启后恢复明确的取消/结算任务，未保存完整局势的活动竞猜列为旧轮，主持人可核对后取消。文件损坏不覆盖原文件；写盘失败明确提示，不阻止本地重置。存在未完成任务时禁止更改站点和密钥。

THCCB 新增 `GET /capabilities`、`GET /rounds/{round_key}/state`、`POST /rounds/{round_key}/abort`，均用既有联动凭据。abort 为未创建轮号持久登记取消，阻止迟到开盘；已结算则返回原摘要、保留奖励。旧服务兼容普通通知和已存在轮次取消，但未知轮号的 404 不能被当成退款成功；升级后点「重试联动」重新探测。先部署 THCCB 的 `returned_cancel_20261023` 数据库迁移和后端，再启用完整恢复能力。

所有扣款、奖励和退款由 THCCB 的原有资金事务、账本和审计处理。本地只发送轮号和答案，不计算奖金、不修改账户余额。

本项目的观众竞猜只保留 THCCB 联动。旧 LLBot / Satori 群消息接入、`g-50%` 作答解析、旧群友榜数据来源、固定观众演示及 QQ JSONL 写入已移除，旧配置中的 `qq` 字段不再使用；已有历史文件和外部 LLBot 服务不会被代码更新删除或停止。观众答题和资金结算由 THCCB 提供，本项目负责展示参与二维码与结算回传的前五名。
