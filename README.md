# Wavelength 心灵波长

本地 / 局域网可玩的《Wavelength(心灵波长)》桌游数字版：两队对抗，Psychic 出题，队友拨杆猜目标位置，对方猜左右。开局可选「原版」或「平衡快局」。

## 文件结构

| 文件 | 作用 |
|---|---|
| `index.html` | 游戏界面结构(本地热座 + 联网控制器/监视器,自动识别) |
| `app.css` | 游戏界面样式 |
| `assets/fantasyguide/` | 幻想指南风格的本地字体、装饰边框、阴阳分隔线和背景素材 |
| `app.js` | 界面渲染、离线模式和联网客户端逻辑 |
| `game.js` | 共享游戏引擎(纯逻辑,浏览器和 Node 通用) |
| `server.js` | Node 服务器:SSE 实时广播 + API + 静态文件服务 |
|  `cards.yaml` | 默认题库(服务器启动时加载) |
| `decks/` | 服务器题库收藏夹,放入的题库文件可在 iPad 上直接下拉选择 |
| `config.json` | 服务器配置(访问密码),已 gitignore |
| `auth-sessions.json` | 已认证浏览器的设备会话(自动生成,仅保存令牌哈希,已 gitignore) |

## 两种玩法

### 1. 本地热座(单设备)

直接双击打开 `index.html` 即可,无需任何服务器。所有玩家围着一个屏幕轮流操作。

### 2. 联网模式(多设备实时同步)

```
node server.js
```

启动后控制台会打印访问地址(本机 + 局域网 IP)。各设备用浏览器打开 `http://<电脑IP>:3100`,选择角色:

- **🎮 控制器**(建议 iPad):负责所有操作——Psychic 看目标位置、选卡片面、拨动拨杆、锁定、猜左右、开始下一轮
- **👀 监视器**(建议电脑/大屏):实时观看,与控制器完全同步,但**永远看不到目标位置**(保持神秘感)

超宽活动屏按 **3904 × 672 实际像素、100% 浏览器缩放**设计：左侧、中央游戏区、右侧分别为 900 / 2048 / 900px 宽。左队的队名、比分和进度在左侧，右队在右侧；左队下方显示回合记录，右队下方显示群友作答，超出空间时自动滚动。候选题目 52px、选定概念 64px、阶段提示 42px、回合记录 40px。队名使用对应队色，常规队名为 88px，上下各留半个字号；长队名根据剩余宽度缩放，比分 136px，进度菱形边长 28px。正反义词之间的横线固定居中，两侧词语分别对齐横线。出题结束后只显示选定题面；题卡、提示、左右选择、色带和结算分别保留固定位置，整个回合不会因新增信息上下跳动。200% 系统缩放对应的 1952 × 336 视口按相同比例适配。

显示与群聊作答使用 **左 −100%、中 0%、右 +100%** 的刻度。控制器点击「规则速查」会同步打开或关闭监视器的规则说明。监视器在终局后直接进入复盘，展示获胜队伍、最后一题、回合记录和本轮群友榜，无需点击「返回复盘」。

## 游戏流程

1. **设置**:填两队名称，选规则版本、先手、题库和出题方式，开始游戏。默认「原版」规则与「二选一」出题：每轮抽取两道题，由出题人点击选择一道后继续；也可切换「经典单题」。
2. **出题**:Psychic 选卡片面 → 点「查看目标」偷看目标位置(**其他人别看屏幕!**)→ 口述一个落在两个概念之间的线索 → 关闭屏幕,**之后不能再说话**
3. **讨论**:本队讨论线索,把金色拨杆拖到猜测位置,锁定
4. **猜左右**:对方猜目标中心楔形在拨杆左边还是右边
5. **揭示**:Psychic 揭示目标——本队得 2/3/4 分(边界取高),对方猜对左右得 1 分(本队完美命中 4 分时对方不得分)
6. 按所选规则结算；如果继续，开始下一轮并更换出题人。一队完成一次出题与结算算一轮，两队各行动一次共两轮。

### 规则版本

| 项目 | 原版（保留本项目现有规则） | 平衡快局 |
|---|---|---|
| 起始分 | 先手 0，后手 1 | 双方 0，不补分 |
| 色带基准宽度 | 默认 40，可在高级选项修改 | 固定 48 |
| 目标分布 | 第 1 轮适中，第 2 轮明显，之后推荐 | 所有轮次推荐 |
| 行动顺序 | 4 分且仍落后时再行动一轮 | 严格交替，无追赶连动 |
| 常规结算 | 先到设定分（默认 10）即结算；最多 10 轮 | 第 4 轮结束，有队达到 8 分则比较总分；否则第 6 轮结算 |
| 平分加时 | 两队各一次，仍平则重复 | 两队各一次，仍平则和局 |
| 总轮数 | 常规最多 10 轮，加时不限 | 常规 4–6 轮，含加时最多 8 轮 |

两种规则均在结算时由分数较高者获胜，平分进入加时。加时比较独立得分（包含猜左右的 1 分），主记分板保持常规赛的平分；界面另行显示两队加时分和是否已出题。加时必须等双方各出一次题后才结算，原版追赶规则不适用于加时。

平衡快局保持双方行动次数相等：例如先手在第 3 轮达到 8 分，仍要完成第 4 轮才比较总分；第 5 轮达到门槛也要等到第 6 轮。其 8 分门槛与宽度 48 为固定参数。原版的分数门槛和宽度仍可自定义，门槛填 0 表示只在第 10 轮结算。

规则版本仅可在开局设置中切换，本地、控制器和监视器使用同一规则状态。点击「再来一局」保留所选版本；切换版本会恢复该版本的默认分数与宽度，不改变题库、出题方式和队名。平衡快局对应 [5 局实测规则及记录](docs/playtests/2026-10-13-balanced-48/report.md)，回归测试会重放其全部 22 轮。

**出题禁忌**：禁用卡片上的词/同义词、数字、复合线索、自造事物。

## 题库系统

### 格式(JSON / YAML 均可)

- JSON:`{"name": "题库名", "cards": [["左", "右"], ["左1", "右1", "左2", "右2"]]}`
- YAML:每行一张卡 `- [左, 右]`;双面卡写 4 个概念 `- [左1, 右1, 左2, 右2]`;`#` 开头为注释
- **2 个概念 = 单面卡**;**4 个概念 = 双面卡**(Psychic 可选"面 A / 面 B"出题)
- 概念文字中请勿使用逗号

### 加载方式

| 场景 | 方式 |
|---|---|
| 联网模式 | 把题库文件放进服务器目录的 **`decks/`** 文件夹 → iPad 控制器下拉选择(改动后点「刷新」) |
| 本地模式 | 点「选择文件…」手动选择;或用过的题库自动记住(localStorage) |
| 默认 | 加载根目录 `cards.yaml`（当前为「车万版」，回退 `cards.json`）；「恢复初始题库」回到这套默认题库，联网模式恢复服务器启动时加载的内容；无默认文件时回退内置 98 张卡 |
| 通用题库 | 原内置 98 张卡保留在高级选项的「其他题库」→「通用题库（原内置）」，本地和联网控制端均可选择 |

## 访问密码(可选)

`config.json`:

```json
{
  "password": ""
}
```

- `""`(空)= 不需要密码
- 设置密码后,每个浏览器首次连接需输入密码;认证成功后使用独立的 HttpOnly 设备 Cookie,同一 IP 下的其他设备不会自动获得权限
- 会话有效期 180 天并记录在 `auth-sessions.json`(只保存令牌哈希),重启服务器无需重输;修改密码或删除该文件可重置所有设备
- `POST /api/logout` 可撤销当前设备会话;从旧版升级后,原 `auth-ips.json` 不会迁移,各设备需重新登录一次
- 密码只保护**联网对局**(控制器/监视器);未认证的设备可以在密码页直接点「🎲 跳过密码,本地热座游玩」,在**本设备**上玩单机热座版(不影响他人联网,下次刷新页面仍可输入密码加入联网)
- 密码比对使用时序安全比较;未认证设备的 API 请求一律 401

## 网络稳定性(现场网络不稳友好)

- **连接状态指示**:页头徽章显示 已连接(绿)/ 重连中(橙,脉冲)/ 连接断开(红),断开时弹出警示横幅并自动禁用操作按钮
- **自动重连**:断线后 1s→2s→4s…→最大 10s 指数退避重连,连上即重置
- **心跳探测**:每 8s ping 一次,连续 2 次失败强制重建连接(兜底 WiFi 掉线等 SSE 不报错的情况)
- **操作队列**:断线期间的操作自动入队,重连后按序补发(连续拨杆只保留最新值)
- **iPad 唤醒**:页面回到前台立即心跳 + 补连
- **服务器保活**:每 15s 发送 SSE 保活帧,防止热点/代理空闲超时掐断连接

## iPad 使用

**单机本地玩**:把 `index.html`、`app.css`、`app.js`、`game.js` 和完整的 `assets/` 目录放在同一目录(可以直接复制整个文件夹),AirDrop/存入 iPad「文件」App,用 **Documents by Readdle** 等文件浏览器打开 `index.html`,自动进入本地热座模式(注意:直接双击文件是打不开的,iOS 需要这类 App 运行 HTML)。

**多人联机**:电脑跑 `node server.js`,iPad 用浏览器访问局域网地址,选「控制器」即可;电脑开监视器观看。

## 在线托管(无后端版,任何人打开网址即玩)

把仓库的**整个根目录**(或仅 `index.html` + `app.css` + `app.js` + `game.js` + `cards.yaml` + `names.json` + 完整 `assets/` 目录)当作静态站点部署到任意静态托管,访问者打开网址即可直接玩**本地热座版**——页面会自动检测到没有后端并进入本地模式。

- 仓库保持私密即可;**`config.json`、`auth-sessions.json` 已被 gitignore,不会随仓库暴露**
- 部署在第三方平台时,托管的是仓库内文件的公开副本(只有游戏代码,无任何秘密)
- 联网模式(控制器/监视器、密码)是 `server.js` 的功能,只能在你自己运行的 Node 服务器上生效

### Netlify(推荐,免费)

1. 打开 https://app.netlify.com 用 GitHub 账号登录
2. Add new site → Import an existing project → 选择私密仓库 `wavelength`
3. Build command 留空 / Publish directory 填 `.`(仓库根目录)
4. Deploy 完成后得到 `https://<名称>.netlify.app` 网址,可自定义域名

### Vercel(免费)

1. 打开 https://vercel.com 用 GitHub 登录
2. Add New Project → Import 私密仓库 `wavelength`
3. Framework Preset 选 Other / Build Command 留空,Deploy
4. 得到 `https://<名称>.vercel.app`

### Cloudflare Pages(免费)

1. https://dash.cloudflare.com → Workers & Pages → Create → Connect to GitHub
2. 选择私密仓库,Framework 选 None,Build command 留空,Build output directory 填 `.`

部署后访问者打开网址即可玩;本机开发/局域网联机仍用 `node server.js`。

## 自定义文案(游戏名 / 术语)

外置文件 `names.json`(与 `index.html` 同目录)用键值替换游戏名和术语,未填写的键用默认值:

```json
{
  "gameName": "Wavelength",
  "gameTitle": "WAVELENGTH",
  "gameSubtitle": "心灵波长",
  "psychic": "Psychic",
  "dial": "拨杆",
  "target": "目标",
  "teamDefaultA": "左脑",
  "teamDefaultB": "右脑"
}
```

联网/静态托管模式下自动加载 `names.json`,改完刷新生效;本地模式可在设置界面「选择文件…」加载并记忆。

## 高级选项(设置界面「⚙ 高级选项」)

- **题库 / 文案**:服务器下拉选 decks、本地文件选择、恢复初始题库（默认车万版），原内置卡片另设「通用题库」入口；文案可恢复默认
- **按顺序出卡**:不洗牌,按题库顺序逐张展示,抽完循环
- **二选一（默认）**:每轮抽两道不同的候选题，选定后才生成目标并进入出题流程；跳过题目会重新抽两题，本轮轮数不变。未选中的题同样计为已抽取；抽完循环。题库只有一道不同的题时，展示该题供确认。双面卡选定后仍可选择卡片面。
- **色带宽度**:以设置中的基准宽度为准，4 分区为 80%，每侧 3 分区为 100%，每侧 2 分区为 110%；默认分别为 32 / 40 / 44。
- **获胜分数**:可改,填 0 表示不设分数门槛(计分轨道显示 ∞),但仍在第 10 局结算
- **倒计时**:查看目标后开始 60 秒倒计时,锁定拨杆后切换为 15 秒;剩余 5 秒时变红并播放一次提示音,归零后仅停在 `00:00`,不会强制推进游戏。可修改 `index.html` 的 `data-dial-timer-seconds` / `data-guess-timer-seconds`,设为 0 可关闭
- **刻度**:在 5% 到 95% 之间固定每 5% 一条,横条下方标注 0% / 25% / 50% / 75% / 100%;两端只显示数字,不画刻度线
- **目标分布**:固定公平模式——第 1 局使用适中分布,第 2 局使用明显分布,第 3 局及以后使用推荐分布

## 测试

测试套件需要 **Node.js 22.22.2 或更高版本**。依赖版本已锁定,首次使用或锁文件变化后安装:

```bash
npm ci
```

运行全部测试:

```bash
npm test
```

真实浏览器测试会自动寻找常见位置的 Chrome/Chromium;如浏览器位于其他位置,设置 `CHROME_PATH=/path/to/chrome`。

覆盖:本地完整对局、10 局结算与平分加时、轮次目标分布、题库上传/目录/路径穿越防护、256 KiB 请求限制、双设备同步与目标保密、独立设备认证/注销/游客流程、静态托管、手机端弹窗滚动、断连→重启→自动重连。

监视器角色在超宽低屏环境（宽度至少 1800px、高度不超过 900px）会自动切换为三栏活动屏布局；已针对 `3904×672` 分辨率验证。

UI 对齐幻想指南与「四权家异变」：白底墨线、燕宋字体、装饰边框和阴阳分隔线；蓝/粉队色、金色拨杆与计分色带保留。字体和装饰素材均在 `assets/fantasyguide/` 本地加载，来源记录见该目录的 README。

### 固定群友预览

设置 `WL_AUDIENCE_DEMO=1` 启动服务器时，群友区域显示五位固定示例用户（昵称、服务器提供的 SVG 头像、百分比答案固定），揭晓后按与实际目标的距离排序。揭晓前不展示目标或误差。此模式只用于 UI 预览，会禁用真实 QQ 连接及竞猜结果存档；不设置该变量时仍使用原有 QQ 配置。

```sh
WL_AUDIENCE_DEMO=1 PORT=3109 node server.js
```
